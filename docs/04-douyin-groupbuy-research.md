# 抖音团购低价票源接入调研（产品视角）

- 阶段：S1 | 调研人：PM | 日期：2026-10-24
- 文档性质：内部产品调研。所有行情描述均为对公开现象的定性判断，不含内部商务数据，不冒充精确数字。

## 一、背景与现象

- 近年部分低成本航司（以春秋航空为代表）及机票代理在抖音通过直播间、团购套餐、"机票盲盒"等形式，销售明显低于常规渠道的机票套餐：用户先购券、后按规则兑换指定航线的出行。【推断-公开现象定性】
- **用户价值**：价格确实低（淡季/冷门航线常有可观折扣），内容化推荐能激发"说走就走"，对预算敏感用户是真实机会。
- **用户风险**：有效期与可约日期受限、退改规则苛刻甚至不可退、宣传库存与实际可约航班不符、必须在抖音 App 内完成下单、售后链路跨平台扯皮。【推断】
- **产品判断**：机会与风险同源——"低价"来自渠道补贴与库存特卖，"坑"来自规则复杂性。FareRadar 的职责是**让机会可见、让风险透明**，而不是替用户承担交易本身。

## 二、接入路径对比

| 路径 | 做法 | 优势 | 门槛与风险 | 结论 |
|---|---|---|---|---|
| (a) 官方渠道 | 申请抖音开放平台（含本地生活开放能力）服务商/开发者资质；或与航司、平台商务合作取得商品数据接口 | 合规、数据实时稳定、可持续演进 | 需企业资质、审核周期、商务谈判，可能涉及分成；个人/教学项目短期不可得 | **目标态**，远期路线 |
| (b) 第三方聚合 | 经有资质的本地生活服务商或聚合数据商间接获取团购商品数据 | 接入快、门槛低一档 | 数据非官方，可能滞后失真；合规责任传导不清；稳定性与成本受制于人 | 仅在无法直接合作时作为备选，接入前必须法务评审 |
| (c) 未经授权爬取 | 爬取抖音页面或非公开接口 | 表面上"零成本" | 违反平台用户协议与反爬机制：账号封禁、法律追责、不正当竞争风险；数据合规风险高 | **项目明确不采用**，任何分支不进仓库、不写爬虫代码 |

**合规底线（PM 声明）**：本项目为教学性质，不以任何形式触碰路径 (c)；路径 (b) 未过法务评审前不立项；一切真实接入只走路径 (a)。

## 三、MVP 结论（V1.0 采纳）

1. **用模拟数据源 + 可插拔适配器接口验证产品价值**：接口先于真实数据，保证未来"换源不换产品"——这是 V1.0 唯一必须为抖音接入做的事。
2. **适配器统一字段契约**（PM 提出的最低字段集，Dev 据此设计适配器接口）：

| 字段 | 说明 | 必填 |
|---|---|---|
| `deal_id` | 套餐唯一 ID | 是 |
| `source_name` | 票源显示名（如"抖音团购源（模拟）"） | 是 |
| `route` | 出发地-目的地 | 是 |
| `price` / `currency` | 价格与币种，必须同时给出含税口径 | 是 |
| `valid_from` / `valid_until` | 有效期起止 | 是 |
| `stock` | 库存或枚举状态（充足/紧张/售罄） | 是 |
| `purchase_entry` | 购买入口描述，必须含"需在抖音 App 内下单"类文案 | 是 |
| `refund_change_rules` | 退改规则全文；缺失时上层必须输出"未披露" | 是（缺失兜底） |
| `updated_at` | 数据更新时间 | 否 |

3. **可插拔的验收含义**：新增一个模拟票源只需实现适配器并注册，`search`/`deals` 逻辑零改动；S3 测试将把这一点作为用例验证。
4. **为什么字段里没有"购买链接"**：V1.0 不出票、不跳转，购买动作永远发生在抖音 App 内；`purchase_entry` 只承载"去哪买、怎么买"的诚实提示，避免工具伪装成交易入口。

## 四、后续里程碑（非承诺，需逐期评审）

- **v1.1**：跟踪抖音开放平台开放能力与资质要求的变化；按真实接口修订字段契约。
- **v2.0**：若获得航司/平台/服务商合作意向，走路径 (a) 小范围试点；接入前完成法务与平台协议评审；真实数据须标注来源与更新时效。
- **原则**：先合规、后接入；未经授权的路径永远不做。

## 用户视角

- **用户能看到什么**：即便未来接入真实团购源，套餐卡仍必含退改规则、有效期、下单提示与数据时效；数据从哪来、新不新鲜，写在明面上。
- **用户能做到什么**：凭卡片信息独立判断"值不值得去抖音下单"，不必进直播间或问客服就能拼齐决策要素。
- **用户会感受到什么**：工具帮我看清机会与坑，而不是把我推进直播间；便宜是真的，规则也是真的。
