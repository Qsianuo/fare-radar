## S21 迭代十六：v1.13.0 春秋券库（截图入库 + 券折算定价，航班查询不含价）

- 起因：产品侧要求"把春秋特价票图片录入数据库 → tool 查可用航班但**不返回价格** →
  按券规则折算实际单价（209 元 2 次卡 → 每次约 104.5 元）"，并明确要交代数据结构、
  匹配规则与最终价格展示逻辑。
- 数据：7 张春秋抖音小程序截图（3 张「209元秋季2次卡」适用航线表 + 4 张「购省钱卡专享机票」
  价目表）人工逐行转录为 `src/data/spring_seed.json`，入库为 4 表 SQLite：
  券 2 / 券适用航线 101 / 日期价目 52。只抄不推：有效期、卡费、税费口径、航班号、
  起降时刻截图没写的一律 NULL。
- 关键裁定：
  1. **两级接口分离**——`spring_flights` 完全不碰价格（返回体无价格语义键、无 `¥`），
     `spring_coupon_quote` 是唯一定价出口。理由：价目是"持卡专享价"，价格从属于券而非航班，
     混在一处必然产生口径错位的比价。
  2. **「可售商品」而不是「航班」**——截图不含航班号/时刻，若渲染成航班就必须编造字段
     （v1.5.0 明令禁止），故字段恒 `null` 并显式声明未披露。
  3. **跨税费口径不排名**——自测发现按金额升序会把"含税费 439"排在"不含机建 180"前面，
     而次卡的税费口径卡面根本没写。改为分组给最低，`best` 仅在全部同口径时给出。
  4. **未披露不猜**：不按"秋季"给次卡编有效期区间，不把 NULL 当 False。
- 实现：`sources/spring_store.py`（建库/入库/城市归一/两级查询/折算/口径分组）+
