## 2. 两个口径裁定（对提交人的正式答复）

1. **到手价口径**：用户真实支付的是含税总价（票价 + 机建 + 燃油）。排序比较与"◀ 最低价"只授予口径可比的结果；仅有不含税价的票源，其结果必须显著披露"税费另计，到手价高于票面"，不得取得"◀ 最低价"，不得触发低价提醒。
2. **券有效期口径**：有效期 = **可出行窗口**（出发日期落在区间内才可用），非"可购买窗口"。依据用户心智（User A 旅程："我要 11 月 3 日飞，这张券 11 月 5 日才开始有效"）。

## 3. 验收标准增量（黑盒可测；编号接续 v1.0 第 4 节）

### 3.1 search（修订 AC1，新增 AC6/AC7/AC8）
- **AC1-R（到手价排序）**：Given 同一结果列表同时存在含税与不含税行，When 展示，Then "◀ 最低价"只落在口径可比（含税）行的最低者上；不含税行必须含"税费另计"类显著披露。Given 列表仅存在不含税行，Then 不出现"◀ 最低价"标记，且口径披露可见。
- **AC6（有效期准入）**：Given 团购券有效期不覆盖搜索出发日期，Then 该券不得取得"◀ 最低价"、不得触发"[低价提醒] 可以出手了"，且"不覆盖"信息必须可见（剔除方案下见提示语，保留方案下行内标注）。Given 剔除后无可比结果，Then 输出"该日期暂无可比报价"类中文提示而非报错。
- **AC7（售罄准入）**：Given 库存为"售罄"的团购券，Then 不得取得"◀ 最低价"；若展示，备注必含"已售罄"。
- **AC8（退改不明标记）**：Given 退改规则缺失的团购券出现在 search 结果，Then 行内带"退改不明"标记。

### 3.2 deals（修订 AC3 兜底文案）
- **AC3-R（用户语言）**：Given 数据源字段缺失，Then 兜底文案必须是用户可懂、可行动的风险提示（含"务必在抖音购买页核对退改条款并截图留证"类指引），禁止出现"字段缺失/数据不完整"等内部术语。

### 3.3 watch 与 alerts 数据保护（新增）
- **AC9（损坏警告）**：Given alerts.json 为非法 JSON，When 任何读取操作执行，Then 输出含"文件已损坏"字样的中文警告与处理建议，不得显示"暂无关注航线"。
- **AC10（不覆盖承诺）**：Given 文件处于损坏状态，When 执行任何写操作（设置/删除），Then 不得以新清单覆盖损坏文件：或先备份原文件再写入（备份方式由技术方案定），或拒绝本次写入；原数据必须可被用户找回。

## 4. 非功能性增量

- **术语红线**：任何面向用户的输出（含错误与警告）不得出现开发者内部术语（如"字段缺失""数据不完整"）。
- **数据保护红线**：宁可拒绝服务，不可静默覆盖用户数据。
- 其余非功能（全中文、仅标准库、≤2 秒、退出码语义）延续 v1.0 不变。

## 5. v1.1.0 明确不做（防范围蔓延）

- 不做税费精确估算：口径归一方案由技术方案定，估算值只作披露参考，不承诺真实税费。
- 不做后台轮询提醒：watch 仍为"查询时判断"（用户旅程第 4 步的误解以 README 措辞修订解决，不改架构）。
- 不做 --json / 颜色高亮 / 历史价格 / 筛选器（仍为 P2 backlog）。

## 6. 成功指标增量

- S5：用户将"◀ 最低价"理解为"我可买到、到手最便宜"——User A 复验其 004/005 场景后确认"箭头敢信了"。
- S6：人为损坏 alerts.json 后，User A 按警告指引能找回或确认原数据未丢。

## 7. 用户视角（铁律自查）

1. **用户能看到什么**："最低价"永远指向"我真能买到、到手真便宜"的那张票；用不上的券会明说哪里用不上（日期不覆盖、已售罄、税费另计）；黑话消失，换成"这种券风险最高，下单前核对退改并留证"这样的人话；关注文件坏了会大声警告。
2. **用户能做到什么**：照 README 完成"找到一张可信的最低价"，不再需要自己核对含税口径、有效期与库存；文件损坏后能按提示找回数据。
3. **用户会感受到什么**：这个工具替我把关而不是怂恿我冲动；它宁愿说"现在没有可信的最低价"，也不给我一个假的箭头；它对我的数据宁可不动手，也不悄悄清空。
