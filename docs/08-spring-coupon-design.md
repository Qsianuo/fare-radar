# 春秋特价票结构化入库与优惠券折算定价（v1.13，ISSUE-022）

> 一句话：**航班接口不给价，价格由券规则算**。先把 7 张春秋抖音小程序截图落成 SQLite，
> 查询时只回答"这条航线这一天有没有券可用"（不含任何价格字段），再由券匹配层折算单价
> （209 元秋季 2 次卡 → 209 ÷ 2 = **104.5 元/次**）。

## 1. 为什么拆成两级接口

需求原文要求"查询春秋航空的可用航班，但查询结果中不返回价格信息"，之后才"按优惠券规则
折算实际单价"。这不是接口洁癖，而是数据现实决定的：

- 截图给的是**券规则 + 适用航线 + 日期价目**，没有航班号、没有起降时刻、没有舱位；
- 春秋的小程序价目是"持卡专享价"，价格本来就从属于卡，而不是从属于某个航班；
- 如果让航班接口顺带返回价格，上层就会拿"票面价"和"券折算价"混着展示，
  必然出现"104.5 和 130 哪个便宜"这种口径错位的比较。

因此两级分离，且第二级是唯一价格出口：

| 级别 | 职责 | 是否含价格 |
|---|---|---|
| `spring_flights` / `GET /api/spring/flights` | 查可兑性与可售日期 | **否**（`price_returned=false`，全字段扫描无价格语义键） |
| `spring_coupon_quote` / `GET /api/spring/quote` | 券匹配 + 折算单价 + 口径分组 | 是（唯一的定价出口） |

## 2. 数据结构

### 2.1 从图片到库的三段链路

```
7 张截图 ──人工逐行转录──> src/data/spring_seed.json ──ingest()──> src/data/spring_aviation.db
                                                              （SQLite，标准库 sqlite3）
```

转录原则（零编造红线）：**只抄不推**。航线名、票价、省额、日期、税费口径逐字照抄；
截图没写的（有效期、省钱卡卡费、航班号、起降时刻）一律 NULL，由上层渲染成"未披露"。
截图不含年份，年份沿用 PRD 裁定的 2026（与 `douyin_miniapp` 的 21 条特价票一致）。

图片来源对应关系：

| 图 | 内容 | 落库去向 |
|---|---|---|
| 1–3 | 「209元秋季2次卡」适用航线表（左/右双栏） | `coupon_route` 101 条 |
| 4–7 | 「购省钱卡专享机票」价目表（去重后） | `fare_offer` 52 条 |
| 全部 | 券面信息（券名、卡价、次数） | `coupon` 2 条 |

### 2.2 四张表

```sql
-- 券（卡产品）
coupon(coupon_id PK, name, face_name, issuer, channel,
       price_cny,       -- 卡价；NULL = 截图未披露（省钱卡没标售价）
       trips,           -- 可兑次数；NULL = 非次卡
       per_trip_cny,    -- 折算单价 = price_cny / trips，入库时算好落库
       tax_included,    -- 1 含税费 / 0 不含机建燃油 / NULL 未披露
       valid_from, valid_until,   -- NULL = 卡面未标注有效期
       match_rule,      -- route_list（按适用航线）| listed_fare（按价目表）
       note, batch_id)

-- 券适用航线（次卡的 101 条白名单，方向敏感）
coupon_route(coupon_id, dep_city, arr_city, dep_code, arr_code,
             PRIMARY KEY (coupon_id, dep_city, arr_city))

-- 日期价目（省钱卡专享价，逐条带出发日期）
fare_offer(offer_id PK, coupon_id, dep_city, arr_city, dep_code, arr_code,
           travel_date,   -- YYYY-MM-DD
           price_cny,     -- 卡面「¥xxx 起」
           saved_cny,     -- 卡面「省¥xxx」
           tax_included,  -- 「含税费等」=1 / 「不含机建燃油费」=0
           batch_id, note)

-- 入库批次（可追溯：哪批图、什么时候、多少条）
ingest_batch(batch_id PK, source_kind, source_note, captured_at,
             image_count, fare_year, ingested_at,
             coupon_count, route_count, offer_count)
```

字段口径要点：

- `dep_city / arr_city` 存**截图原文城市名**（如「扬州(泰州)」「揭阳(潮汕)」「台北(中国台湾)」），
  不做归一；`dep_code / arr_code` 是可空的**查询辅助索引**（截图只给中文名），
  未核实的城市留空，只支持中文名查询——宁可查不到，也不给一个可能错的码。
- `per_trip_cny` 落库而不是运行期临时算：104.5 是用户点名的交付值，应当可被直接审计。
- `tax_included` 三态（含税/不含/未披露），**不允许**用 False 兜底 NULL。

### 2.3 入库是幂等的

```bash
python src/spring_ingest.py --rebuild --show
# 入库完成：SPRING-2026-10-26
#   券 2 张 ｜ 券适用航线 101 条 ｜ 日期价目 52 条
```

`ingest()` 每次整表重建，重复执行不产生重复行；库不存在时任何查询会自动建库。

## 3. 优惠券与航班的匹配规则

### 3.1 五条硬规则

| # | 规则 | 实现 | 反例（会被拒绝的做法） |
|---|---|---|---|
| 1 | **航线精确匹配**：`dep_city` 与 `arr_city` 双向都要对上，方向敏感 | `WHERE dep_city=? AND arr_city=?` | 不做「同城/邻近机场」模糊匹配；不把 `上海→石家庄` 当成 `石家庄→上海` |
| 2 | **承运人唯一**：所有券只对春秋航空(9C) 自营航班生效 | `CARRIER_CODE = "9C"` 固定输出 | 不与其它航司比价行混算，不进 `search_flights` 比价列表 |
| 3 | **一次一券**：一名旅客一次单程只能用一张券 | 结果并列展示，`best` 只在同口径内挑一个 | 不做券叠加、不做「次卡 + 省钱卡」组合价 |
| 4 | **日期规则随券类型**：次卡不绑日期（卡面未标有效期），省钱卡按价目表日期精确匹配 | 见 3.2 / 3.3 | 省钱卡日期不匹配时**不外推**到邻近日期 |
| 5 | **未披露不猜**：卡面没写的字段不填默认值 | 全部 `NULL` → 渲染"未披露" | 不给次卡编一个有效期，不给省钱卡编一个卡费 |

### 3.2 209 元秋季 2 次卡（`match_rule = route_list`）

- **命中条件**：`(出发, 到达)` 出现在 `coupon_route` 的 101 条里，即命中；不看日期。
- **为什么不看日期**：卡面只写"209元秋季2次卡"，没写有效期起止。按规则 5 不编有效期，
  因此任何日期都返回同一单价，同时输出警告 `有效期未披露（卡面未标注），可兑日期以下单页为准`。
- **不是"全航线通用"**：只有 101 条白名单内的航线可兑。例如 `上海→石家庄`、`银川→广州`
  都不在白名单里，只能命中省钱卡或直接返回"无可用商品"。

### 3.3 省钱卡专享价（`match_rule = listed_fare`）

- **命中条件**：`fare_offer` 存在 `(出发, 到达, travel_date = 查询日期)` 的记录。
- **日期必须精确**：价目表是逐日定价（同一航线 130 元对应 11-09，换个日期就可能是别的价）。
  查询日期没有记录时，返回 `unit_price_cny = null` + `candidate_dates`（价目表收录的日期与价格），
  **绝不外推、绝不取均值**。
- **未给日期时**同样只给候选日期，不给单一价——避免把不同日期的价压成一个数。

### 3.4 城市入参归一

用户可传三字码、中文名或常用别名，`resolve_city()` 统一归一：

| 输入 | 归一结果 |
|---|---|
| `SHA` / `上海` | 上海 |
| `SWA` / `揭阳` / `潮汕` / `汕头` | 揭阳(潮汕) |
| `扬州` / `泰州` | 扬州(泰州) |
| `十堰` / `武当山` | 十堰(武当山) |
| `黔江` | 黔江(重庆) |

识别不了的城市直接报错（`城市无法识别`），不静默返回空。

## 4. 最终价格展示逻辑

### 4.1 折算公式

| 券类型 | 单价公式 | 示例 |
|---|---|---|
| `route_list`（次卡） | `单价 = 卡价 ÷ 次数` | 209 ÷ 2 = **104.5 元/次** |
| `listed_fare`（省钱卡） | `单价 = 当日专享价` | 2026-11-09 上海→大连 = **130 元** |

- 单位统一为 **元/人次/单程**；
- 金额精度：整数不带小数尾巴（130 而非 130.0），半分位保留（104.5）。

### 4.2 税费口径分组（这是本版最重要的一条展示规则）

**不同口径的单价不合并排名。** 理由很直接：含税费的 ¥439 和不含机建燃油的 ¥180 放在一张
榜上排先后，用户照着低价下单才发现还要付税费——这是误导，不是"聪明"。

所以输出分三层：

1. `quotes`：逐券罗列，各自带 `price_basis`；
2. `basis_groups`：按口径分组，每组给该口径内的最低价；
3. `best_unit_price_cny`：**只有全部命中券同口径时才给**，否则 `null` + `best_reason`
   说明"口径不一致，不自动排名"，并附 `cross_basis_note` 列出各组金额。

三种口径标签：`含税费等` / `票面价（不含机建燃油）` / `税费口径未披露`。

### 4.3 缺字段怎么显示

| 情况 | 展示 | 绝不这样做 |
|---|---|---|
| 卡面未标有效期 | `未披露（卡面未标注有效期）` + ⚠ 警告 | 编一个"秋季"区间 |
| 税费口径未知（次卡） | `税费口径未披露` + ⚠ 提示"到手价需另加税费" | 当成不含税或含税 |
| 省钱卡卡费未展示 | ⚠ `卡费未披露，本单价不含卡费摊销` | 编一个卡价再摊到单价里 |
| 航班号/起降时刻未披露 | `flight_no = null` + `flight_info_disclosed = false` | 用生成值填充（v1.5 已明令禁止） |
| 该航线无券 | `miss_hint` 给出收录范围（101 条航线 / 52 条价目 / 日期区间） | 返回 0 元或空价格 |

### 5.3 三入口同源

| 入口 | 用法 | 规则来源 |
|---|---|---|
| MCP | `spring_flights` / `spring_coupon_quote` | `sources/spring_store.py` |
| Web | `GET /api/spring/flights` / `GET /api/spring/quote`（页签「春秋券」） | 同上（`webapp` 只做 HTTP 翻译） |
| CLI | `python src/fareradar.py spring --from 上海 --to 通辽 --date 2026-11-04` | 同上 |

CLI 输出刻意分三段：① 可用商品（无金额）→ ② 券折算 → ③ 口径分组。第①段不出现任何
`¥`，从输出形态上就防止"票面价混进航班表"。

## 6. 与既有春秋数据线的关系

| 模块 | 卖什么 | 产出 |
|---|---|---|
| `douyin_miniapp` | 21 条固定日期特价票 | 比价行（进 `search_flights`） |
| `douyin_groupbuy` | 次卡/省钱卡等卡面商品 | `card_hints`（不参与比价） |
| **`spring_store`（本版）** | **券规则 + 适用航线 + 日期价目** | **券定价层（不进比价行，价格只由券算）** |

三者**不重复计数**：本层不产出比价行，因此不会与 21 条特价票在同一张比价表里撞车；
它回答的是另一个问题——"用券到底多少钱一次"。

## 7. 已知边界（明确不做的事）

1. **没有航班号与起降时刻**：截图未披露，本层不生成。想要真实时刻需接春秋官方接口（目前无面向第三方的公开接口）。
2. **不校验库存与可售性**：价目表是静态截图，无法确认某一天是否真的还有座；输出统一提示"以下单页为准"。
3. **省钱卡卡费未知**：单价是持卡成交价，不含卡费摊销，已在每张券上标注。
4. **次卡有效期未知**：卡面未写，因此不做日期过滤，只用警告提示。
5. **不爬取**：数据全部来自人工转录的截图，不触碰任何平台的服务条款。

## 8. 测试

`tests/test_spring_coupon.py`（24 例），按需求三条验收线组织：

- 入库：101 / 52 / 2 的逐项断言、重复入库幂等、104.5 落库、未披露字段必须为 NULL；
- **不漏价**：递归扫描返回体所有键与字符串——除 `price_returned` / `price_note` /
  `price_basis` 三个声明性键外不得出现价格语义字段，且全文不得出现 `¥`；
  航班号/时刻必须为 `None`；
- 折算：航线命中即 104.5、白名单外只有省钱卡、日期不符不外推、无日期只给候选、
  跨口径不排名、同口径才给最低、未知城市报错；
- 三入口同源：Web API 与 MCP 文本复用同一规则（MCP 航班文本断言不含 `¥`、折算文本含 `¥104.5`）。

运行：`python -m unittest discover tests`（全量 222 例）。
