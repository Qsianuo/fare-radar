# FareRadar 需求调研记录（S1）

- 阶段：S1 需求 | 调研人：PM | 日期：2026-10-24
- 方法与局限：本阶段为桌面调研（对公开产品现象的定性观察）+ 角色假设推演。真实用户访谈尚未进行（User A 为模拟角色，其真实反馈将在 S3 用户旅程中产生）。因此本文结论分三级标注：
  - 【已确认】来自项目宪法或总协调者拍板，不可推翻，除非走流程变更；
  - 【推断】有公开现象支撑，但未经真实用户验证；
  - 【假设】纯产品判断，待 S3 Tester 黑盒与 User A 旅程验证。

## 一、目标用户画像（User A）

- **基本盘**：小林，24 岁，二线城市初级职员/在读研究生，月可支配收入约 4000 元。
- **出行场景**：每年 2-4 次——法定假期返乡（时间刚性，提前 2-6 周购票）；淡季一次休闲旅行（时间灵活，愿意为省 200 元改期出行）。行李少，能接受廉价航空与红眼时段。
- **行为特征**：购票前会在 2-3 个 App 之间反复比价；刷抖音时刷到过航司直播间"团购券/机票盲盒"，心动过，但担心"便宜没好货、不能退、还要专门去抖音 App 下单"。
- **标注**：【假设-待验证】画像为产品假设；S3 将通过用户旅程验证"价格敏感 + 怕踩坑"两大动机是否成立，以及 3 分钟门槛是否现实。

## 二、五问五答

### Q1 用户是谁？场景是什么？
**结论**：核心用户是预算敏感、时间有一定弹性的年轻旅客（学生/初入职场者），主场景是"出行前 2-6 周的购票比价期"，次场景是"刷到低价团购后想搞清楚能不能买"。【推断】

### Q2 核心痛点是什么？
1. **票源分散**：航司官网、OTA、抖音直播/团购三套体系互不相通，逐个查费时费力。【推断】
2. **团购票信息不透明**：有效期、可约日期、退改规则、剩余库存、下单路径，往往要进直播间或问客服才能拼凑齐。【推断】
3. **担心低价是套路**：怕"低价引流实际买不到"、怕不同渠道含税口径不一致导致比了假、怕售后跨平台扯皮。【推断】

### Q3 现有产品为何不够？
- **OTA（携程/飞猪/去哪儿）**：比价范围不含抖音团购渠道，团购券类商品不进机票搜索结果。【推断】
- **抖音站内**：有团购商品，但无跨店横向比价，退改规则非结构化展示，冲动下单风险高。【推断】
- **航司官网/小程序**：只卖自己的票，天然不比价；不看直播拿不到团购价。【推断】
- **既有低价提醒类产品**：基于航司/OTA 报价，不覆盖团购渠道。【假设】

### Q4 我们解决什么？V1.0 最重要的功能是什么？
**结论**：把"多票源价格合并排序"与"团购票的坑显式披露"装进一个零门槛的本地小工具。V1.0 最重要的是**搜索比价**（找到最低价是北极星），**团购专区**（透明披露）紧随其后，**低价提醒**（P1）轻量跟进。【已确认：3 命令范围由总协调者拍板；优先级划分由 PM 裁量，见 PRD 4.1】

### Q5 如何判断"满足了"？
- 用户仅凭 README，3 分钟内完成一次搜索并正确说出"最低价是多少、来自哪个票源"。【假设-待 S3 验证】
- 用户能复述任一团购套餐的退改限制与下单方式，主观反馈"没意外"。【假设】
- 用户明确知道数据是模拟的、工具不能出票，没有产生"这是真实报价"的误解。【假设】
- 详细指标见 PRD 第 6 节（S1-S4）。

## 三、给 PRD 的范围输入（小结）

1. 收敛为 3 个命令：搜索比价 / 团购专区 / 低价提醒；不做购票、支付、真实数据。
2. "诚实披露"升级为红线：模拟数据声明、退改规则、需抖音 App 下单提示缺一不可。
3. 票源架构必须可插拔，字段契约见 04-douyin-groupbuy-research.md。

## 四、待真实用户验证清单（带入 S3）

1. "3 分钟找到最低价"对真实用户是否成立（操作门槛 vs 认知门槛）。
2. 团购卡五要素（价格/航线/有效期/退改/下单提示）是否够用，是否还需要"直播间入口"等字段。
3. 低价提醒"查询时判断"（非后台轮询）能否满足等待降价的场景。
4. "是否含税"口径标注是否被普通用户正确理解。

## 用户视角

- **用户能看到什么**：本文档决定了产品界面上"必须出现什么"——模拟数据声明、退改规则全文、抖音下单提示，都是调研中痛点 2/3 的直接映射。
- **用户能做到什么**：3 分钟找到最低价是唯一硬门槛，达不到即产品失败。
- **用户会感受到什么**：目标感受是"可信、省心、不套路"——便宜看得见，坑写得明。
