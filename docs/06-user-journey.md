# 06 用户旅程记录（User A · 真实用户试用）

- 日期：2026-10-24 晚
- 我是谁：25 岁，在上海上班，预算敏感。明年想去大阪，五一要回成都老家。同事在抖音直播间抢过便宜机票券，我心动但怕被坑。朋友推荐了这个工具，我拿到手的就是一个文件夹 + 一份 README，其他啥也不懂。

## 我的三个目标

1. 查一下 11 月中上海→成都有多便宜
2. 看看抖音团购券到底便宜多少、有什么坑
3. 我担心涨价，想让它帮我盯着

---

## 第 1 步：照着 README 抄第一条命令（目标①）

我做了什么：打开 README"3 分钟上手"，把示例原样复制到 Git Bash 里跑。

```
$ python src/fareradar.py search --from SHA --to CTU --date 2026-11-15
航线：上海(SHA) → 成都(CTU)   日期：2026-11-15（周日）
¥459  抖音团购源(模拟)  川航联营 上海-成都 双城券     含税    团购 ▶ 需抖音App下单｜有效期 2026-11-15~2026-12-10
      ◀ 最低价
¥650  模拟航司源        9C8905                        不含税  春秋航空 直飞，无免费餐食
```

我的感受：第一次就跑通了，输出跟 README 里印的一模一样，最低价 ¥459 下面还有个小箭头，一眼能看到。顶部那行"[模拟数据]"虽然提前给我泼了冷水（不是真票价），但至少它没骗我。**这一步是爽的。**

卡点：SHA、CTU 这些"三字码"我不认识，全靠抄示例。要是我想查别的城市就抓瞎了（下面真的抓瞎了）。

## 第 2 步：顺便查大阪（目标①的私心）

我做了什么：明年想去大阪，我不知道大阪的三字码，凭直觉猜了 OSA（大阪拼音缩写）。

```
$ python src/fareradar.py search --from SHA --to OSA --date 2026-12-20
该航线暂无可用报价（已接入票源：模拟航司源、抖音团购源(模拟)）。
可尝试已有航线，如：search --from SHA --to KIX --date 2026-12-20
```

我的感受：它没崩、没骂我，还提示我试试 KIX。但两个别扭：①我猜错的三字码被原样当航线显示成"上海(SHA) → OSA"，我还以为真有这条线只是没票；②KIX 是啥我还是不知道，是后来自己反应过来大概是关西机场。跟着提示抄，大阪查出来了。

```
¥1009  模拟航司源        9C8999                        不含税  春秋航空 浦东-关西 直飞
       ◀ 最低价
¥1099  抖音团购源(模拟)  春秋航空 上海-大阪 5日有效券  含税    团购 ▶ 需抖音App下单
```

**这里我皱眉了**：最低价 ¥1009 标着"不含税"，团购券 ¥1099 是"含税"。这俩根本没法直接比——¥1009 加上税到底比 ¥1099 便宜还是贵？工具吹"最低价一眼可见"，但这个"最低"我信不过：万一加上税它反而更贵，那这个 ◀ 标记就是把我往坑里带。我最后要付的可是含税总价。

## 第 3 步：扒团购券的坑（目标②）

我做了什么：按 README 第 3 步查团购专区，先看成都，再不带参数把 5 张券全逛了一遍。

```
$ python src/fareradar.py deals --from SHA --to CTU
```

（摘录，成都最低那张 ¥459）

```
┌ 套餐：川航联营 上海-成都 双城券 [DY-005]
│ 价格：¥459（含税）｜库存：充足
│ 退改规则：未披露，下单前请在购买页确认
│ 限制条件：模拟源数据不完整：退改规则字段缺失
```

我的感受，好坏掺半：
- **好的**：有效期、退改规则、下单方式都印在卡面上。大阪那张券把"出票后不可退不可改、不含行李额、往返需提前 7 天预约"写得清清楚楚——这正是我在直播间被种草时最怕看不到的东西。它甚至让我别急着买，先看清退改。这部分我信任它。
- **别扭 1**：最便宜的 ¥459 双城券退改规则是"未披露"，还跟着一行"模拟源数据不完整：退改规则字段缺失"。这后半句是啥？像程序内部的话直接怼我脸上。更讽刺的是：团购最大的坑就是退改，结果恰恰是最便宜那张坑最大、还让我自己"去购买页确认"。那我看这工具图啥？
- **别扭 2**："3日有效券"名字叫 3 日，有效期却写着 11-01~11-30 整月，没地方解释这"3 日"到底指啥。

**揪到一个大坑**：逛全量列表时看到京沪券 DY-004"库存：售罄"，我灵机一动反查搜索：

```
$ python src/fareradar.py search --from PEK --to SHA --date 2026-11-10
¥599  抖音团购源(模拟)  京沪快线 15日有效券  含税    团购 ▶ 需抖音App下单｜有效期 2026-11-01~2026-11-15
      ◀ 最低价
```

它把一张**售罄的券**当"最低价"排第一，备注里半个字不提买不了。我要是信了它，兴冲冲跑去抖音 App，结果是空欢喜。README 明明说"坑全部写在明面上"——售罄这个坑它自己藏起来了。

## 第 4 步：设底价盯降价（目标③）

我做了什么：今天最低 ¥459，我怕它涨，把心理底价设成 ¥500，然后立刻检查了一遍。

```
$ python src/fareradar.py watch --from SHA --to CTU --price 500
$ python src/fareradar.py watch
已保存关注：上海(SHA) → 成都(CTU)，底价 ¥500。
[低价提醒] SHA → CTU 当前最低 ¥459 ≤ 底价 ¥500，可以出手了！
共 1 条航线命中底价。
```

之后我又跑了一次 search，顶部果然出现"[低价提醒] 当前最低 ¥459 ≤ 你的底价 ¥500，可以出手了！"，`watch --list` 也能看到我的关注。**功能都是真的，这一步也顺。**

卡点（说清楚但不算欺骗）：README 第 4 步写"设个心理底价，**等**降价提醒"，我以为像抢票 App 那样它在后台帮我盯着、降价了会通知我。实际上我得**自己天天开终端敲一遍 watch** 它才看一眼——这藏在 README 最后的"已知限制"里。作为普通用户，"等"这个字让我误会了。就算它提醒我"可以出手了"，模拟数据也不是真票价，我出手也无从出起，多少有点空欢喜。

用法示例：python src/fareradar.py search --from SHA --to PEK --date 2026-11-15

## 用户综合感受

**对我有用吗？** 有用，但没到"离不开"。它把同一条航线的直飞价和团购券摆在一起、把有效期退改印在明面上、还主动反复提醒"这是模拟数据别当真"——对一个被直播间低价券撩拨得心痒痒的人，它是一份诚实的"避坑清单"。我看完确实冷静了一些：团购券便宜的代价是不可退改、限日期、不含行李，这账它帮我算明白了。

**我下次会打开它吗？** 会，但频率取决于两件事修不修：①别再把售罄的券标成"最低价"，这是我今天最不想原谅的一处——它整个卖点就是"坑写在明面上"，结果最大的坑自己捂着；②"最低价"的口径统一成含税，不然那个 ◀ 箭头我不敢信。

**哪里留住我**：零安装、三条命令、报错说人话、模拟数据声明理直气壮。**哪里劝退我**：三字码门槛（想查的城市得先上网查机场代码）；含税/不含税混着排；开发者术语（"字段缺失"）漏到界面上；"watch"听着像后台管家，实际要我自己勤快。

一句话：它像一个懂行的朋友帮我抄底价、画重点，靠谱；但偶尔会把过期传单（售罄券、没含税的价）也塞给我，我得留个心眼。

## v1.1.0 验收感受（User A · 2026-10-25）

收到更新公告（releases/RELEASE-v1.1.0.md），还是那个我，照旧用当初同样的命令重跑了一遍，逐个对账。

**三个卡点的账，都平了：**

- **售罄券**：¥599 京沪券还在列表里，但行尾多了"已售罄，暂时抢不到"，"◀ 最低价"没了，顶部还明说"没有口径可比的最低价，原因见各行备注"。不白跑抖音了。
- **大阪那个箭头**：现在指向 ¥1099 含税的团购券；¥1009 不含税的垫了底，行内标注"税费另计，到手价高于票面"。它把"票面价做不了数"摆到我眼前——这个箭头我敢照着做决定了。
- **成都最便宜的券**："模拟源数据不完整：字段缺失"消失了，换成"商家未公布退改规则，此类券风险最高……并截图留证"；搜索结果行尾还带"退改不明"。黑话退场，人话上岗。

**回归检查**：成都/大阪查询、猜错三字码的友好提示、团购专区卡面、watch 设底价和低价提醒——原来顺的地方全都没坏。排序确实变了（不含税、用不上的券往后排），但公告提前说了"这不是退步，是修正"，我认同。

**两处小别扭（不算 bug，下次顺手可改）**：
1. 低价提醒喊"可以出手了！"的时候没顺带说这张券"退改不明"，风险写在下面结果行里，得自己往下看一眼才对上——要是提醒里也带一句就周到了。
2. watch --list 里躺着一条不是我设的关注（SHA→PEK，别人测试留下的）。这提醒我"关注清单"跟着文件夹走，共用电脑都能看见，倒不算缺陷，但共用机器的朋友留个心。

**结论**：ISSUE-004/005/006 我都验过，同意关闭。上次说"下次会不会打开取决于两件事修不修"——两件都修了，这版的箭头终于只指我真能买到的便宜，我会一直用到真去大阪那天。
