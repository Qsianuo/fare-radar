## 一、逐单修复任务与判定标准

### ISSUE-001 含税/不含税混排（P1，并入 005 的 KIX 案例）
- 期望方向: 排序与"◀ 最低价"只基于口径可比的价格；不含税结果显著披露"税费另计"。归一估算、分组展示或退出竞争任选。
- 判定标准（黑盒可测）:
  1. `search --from SHA --to PEK --date 2026-11-03`：存在可比含税行时，不含税行（CZ3908 ¥820）不得取得"◀ 最低价"，且行内含口径披露；
  2. 同输入、先设底价 ¥850：不得因 ¥820（不含税）触发"[低价提醒] 可以出手了"；
  3. `search --from SHA --to KIX --date 2026-12-20`（005 案例）：¥1009 不含税不得标"最低价"，与 ¥1099 含税的处理符合 AC1-R；
  4. 仅含不含税结果的输入：无"◀ 最低价"标记且披露可见。
- 回归责任: Tester 复跑 TC-18 + 005 用例；User A 复验其原报告场景。

### ISSUE-002 alerts.json 损坏静默清空（P1）
- 期望方向: 损坏即警告；任何写操作不得以新清单覆盖损坏文件（先备份或拒绝写入，方案自选）。
- 判定标准（按提交人复现步骤原样）:
  1. 损坏后裸 `watch`：输出含"文件已损坏"字样的中文警告与处理建议，不得显示"暂无关注航线"（退出码语义由技术方案定，但警告必须出现）；
  2. 损坏后执行设置/删除：原损坏文件内容必须保留（有备份或写入被拒），原关注数据可找回；
  3. 正常路径不回归（TC-08/09/10 全过）。
- 边界: 只处理"文件损坏"；并发写锁仍是已知限制，不要求本期解决。

### ISSUE-003 有效期不覆盖仍推荐"出手"（P1，口径已裁定）
- 口径: 有效期 = 可出行窗口（PRD v1.1 第 2 节）。期望方向: 做准入校验（整体剔除，或保留+行内显著警告均可）。
- 判定标准:
  1. `search --from SHA --to PEK --date 2026-11-03`（DY-002 有效期 11-05 起）：该券不得标"◀ 最低价"、不得触发"可以出手了"、"不覆盖"信息可见；
  2. `search --from SHA --to CTU --date 2026-10-24`（DY-005 有效期 11-15 起）：同上；
  3. 有效期覆盖出发日期的券行为不变（TC-01 回归通过）；剔除导致列表为空时输出中文提示而非报错。
- 注: 与 001/004 同改"最低价准入"，建议一个分支一次改完，但三单各自留 Reproduce/Fix 记录。

### ISSUE-004 售罄券标"最低价"（P1）
- 期望方向: 售罄券不参与"最低价"竞争；展示时明示库存状态。
- 判定标准: `search --from PEK --to SHA --date 2026-11-10`（DY-004 售罄）：不得标"◀ 最低价"，若展示备注必含"已售罄"；`deals` 卡片库存展示不回归（TC-05 过）。

### ISSUE-006 内部术语透出 + 退改不明标记（P2）
- 期望方向: 兜底文案用户化并给行动指引；search 加"退改不明"标记。
- 判定标准:
  1. `deals --from SHA --to CTU`（DY-005）：退改规则行为用户语言风险提示（含"务必在抖音购买页核对退改条款"类指引与留证建议）；"限制条件"行不再出现"模拟源数据不完整/字段缺失"类内部术语；
  2. search 结果中退改不明的券行带"退改不明"标记；
  3. 扫描三命令全部输出路径（含错误与警告），零内部术语透出。
- **特别约束: 不许往模拟数据里补 DY-005 的退改规则来"消灭"场景**——缺字段是"未披露"兜底的测试资产，必须保留。

## 二、通用要求

- 每单生命周期留痕: Reproduce（复现结果+根因）写回 issue 文件 → fix 分支 → PR 落盘 prs/ → **评审通过后再合并**（落实 PR-001 意见 4）→ Tester 回归 → User A 验收（004/006 必须 User A 本人）→ PM 关闭。
- 单测: 为每个修复点补可断言用例；既有 21 例不回归、全绿。
- README: 行为变化处（最低价口径、售罄/退改不明标记、损坏警告）必须同步；README 示例输出逐字比对是 QA 固定用例，改行为不改文档 = 回归失败。
- 红线不变: 仅 Python 标准库、无真实网络请求、单命令 ≤2 秒、全中文。

## 三、不许顺手改（范围红线）

1. **不许修改模拟数据集来"消灭"缺陷场景**: DY-004 保持售罄、DY-005 保持缺退改、不含税票价结构保持——这些是缺陷的活体复现资产。
2. 不许实现 P2 backlog 项: --json、颜色高亮、历史价格、筛选器。
3. 不许改 alerts.json 的位置与既有字段结构（origin/destination/threshold/created_at）；仅备份文件方案允许新增文件。
4. 不许引入第三方依赖。
5. 不许重构超出修复需要的代码: CLI 参数语义、票源注册表结构、"◀ 最低价"标记符本身不动。
6. **许可的附带小修（仅两处 README 措辞，来自 Tester/User 保留意见，不开 Issue）**: ①"已接入航线"表述改为明确"以上海(SHA)为一端的 5 条有向航线"；② watch"等降价提醒"改为"每次运行时检查一次"（消除用户旅程第 4 步的"后台盯梢"误解）。

## 四、修复完成后的验收流程

1. Dev: Reproduce/Fix 写回各 issue → PR-002 落盘 prs/，逐条对照本文判定标准自测留证。
2. 总协调者: Code Review，重点核对"不许顺手改"清单与各判定标准，结论写回 PR。
3. Tester: 回归 = 原 3 条失败用例（TC-18/19/20）+ 004/005/006 复现命令 + 既有 17 条不回归 → docs/05 补充回归节。
4. User A: 以用户身份复验其提交的 004/006（005 随 001），写 User Acceptance 节，明确"通过/不通过"。
5. PM: 全部通过后逐单写 Closed（关联 PR-002/版本 v1.1.0），正式关闭 005；发布说明 RELEASE-v1.1.0 以用户视角回答"现在的最低价为什么可信了"。
