# 交接说明：PM → Dev（S8 → v1.3.0 实现任务书）

- 交接人: PM | 接收人: Dev（经总协调者中转）| 日期: 2026-10-25
- 范围: ISSUE-009 七点反馈 → v1.3.0。口径依据 docs/02-PRD-v1.3.md（含城市注册表与票源家族清单）；本文只定分工边界、完成判定与范围红线。

## 一、后端任务

1. **城市注册表模块**: 25 城清单（PRD 第 4 节，含三字码/中文名/大致经纬度）为唯一事实来源；网页下拉数据、CLI 校验、定价引擎统一读取；新增城市只改注册表。
2. **任意航线定价引擎**: 替换航司源硬编码 5 航线——按大圆距离生成基础价 + 确定性因子（航线/票源特征/星期/舱位）；注册表内任意起讫组合出价；"该航线暂无可用报价"兜底话术保留（同城市/无效码）。
3. **演示波动**: 分钟级确定性因子（**禁用随机数**）；同一分钟内 CLI 与网页同航线同票源价格一致；分钟间可见变化；幅度由技术方案定，不得产生 0 元/负数、不得破坏含税口径。
4. **票源家族**: 5 个适配器（PRD 第 5 节），全部走 sources/ 注册表，新源自动进 CLI 比价；display_name 去术语化；CLI 行内名同步、首行声明措辞统一为"演示数据"；既有售罄/缺退改/不含税等测试资产场景必须在新家族中延续存在（重新落位到语义相符的票源上）。
5. **收藏数据演进**: alerts.json 底价允许为空（null），存量数据完全兼容；CLI watch 提示语同步（命令名与参数不变）。
6. **API 契约由研发定义**: 在现有 /api/search /api/deals /api/watch* 基础上新增城市全集端点、仪表/24h 曲线端点；定义后同步给前端并回填技术方案文档。PM 只锁语义：城市端点返回全量中文清单；搜索结果含票源显示名/含税口径/风险标记字段；仪表端点返回当前最低价 + 今日区间 + 24h 曲线数据。

## 二、前端任务

1. **城市下拉**: datalist 改完整中文 select（25 城全量可选）——直接修复"只剩一个城市"的过滤缺陷。
2. **收藏航线页**: 列表 + 每条航线当前最低价 + 低于底价绿色标记（绿色唯一语义）+ 删除；"低价提醒"解释性文案删除。
3. **首页仪表**: 大字号最低价 + SVG 弧形表盘或价格区间条 + 近 24 小时演示曲线；常驻"演示数据/演示波动"标注。
4. **UI 升级**: 按 PRD 第 9 节 5 条设计原则落地，纯 CSS，无外部资源。

## 三、完成判定

- 逐条对照 PRD v1.3 第 10 节 AC1-AC8，黑盒可测；**AC8 回归必须全过**（到手价/有效期/售罄/退改不明准入、alerts 损坏保护、退出码不回退）。
- 单测补齐：城市注册表完整性、任意航线出价、波动确定性（同分钟一致/跨分钟变化）、收藏空底价兼容、五票源注册；既有测试断言随票源显示名变化更新（属授权改动）。
- 文档同步：README/技术方案随票源名、城市全集、收藏表述更新。

## 四、不许顺手改

1. 不许引入外部 CDN/框架/图标库/字体；纯 Python 标准库 + 原生 HTML/CSS/JS。
2. 不许做"每秒/实时"波动或随机定价（确定性是硬约束）；页面禁止出现"实时/秒级/行情"字样。
3. 不许改 CLI 参数语义与退出码约定。
4. alerts.json 既有字段不动（threshold 允许为空是唯一授权演进）。
5. 不许删除测试资产场景：售罄券、缺退改券、不含税报价必须继续存在。
6. 真实数据、购票、部署上线、用户系统仍不做。
7. 不做像素稿之外的"自创大改"：UI 超出第 9 节原则的发挥先提 PR 描述说明。

## 用户视角

- 判定不是"页面好看了"，而是评审人重走 7 点反馈逐条点头：中文城市能选、票源看得懂、价格会动且如实标注"演示波动"、收藏一眼见底价、仪表像产品——同时页顶永远有一行字提醒"这是演示数据"。
