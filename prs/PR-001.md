## 实现范围对照（PRD 4.5 优先级总表）

- **P0 全部实现**：search 合并排序 + `◀ 最低价` + 票源标注；deals 团购卡五要素 + "需在抖音 App 内下单" + "未披露"兜底；所有含价格输出首行模拟声明；可插拔适配器（新增源只登记 `sources/__init__.py`）。
- **P1 全部实现**：票源失败降级提示（"XX 源暂不可用"）；watch 低价提醒（设置/列表/删除 + search 时判断 + 裸 watch 全量检查）。
- **P2 未实现（按计划）**：`--json`、历史价格、筛选器、颜色高亮。
- **技术决定**（详见 docs/03 第 6-7 节）：单文件入口 `python src/fareradar.py`；提醒存仓库根 `alerts.json`；`--from/--to/--date` 英文 flag + 三字码值（输出层用中文城市名补偿）。

- 错误路径：日期格式非法/早于今天/参数缺失/未知票源均中文报错且退出码 2；注入故障源后其余票源照常展示。
- 零网络请求；单次命令毫秒级返回（PRD 性能 ≤2 秒）。

## 风险与已知限制

1. 全部为模拟数据与模拟航线；未覆盖航线输出"暂无可用报价"，不编造。
2. 中文表格对齐依赖等宽字体；比例字体终端会错位（信息不丢失）。
3. `collect` 对票源异常只显示降级提示，不打印堆栈（面向用户的取舍）。
4. `alerts.json` 无并发锁，多终端同时写可能互相覆盖（单机单用户可接受）。
5. 不做购票/支付/跳转；团购购买始终在抖音 App 内完成。

非阻塞意见：

1. **【比价公平性，建议 P1】**search 将"含税"与"不含税"行混在一起按票面价排序：冒烟中 CZ3908（¥870 不含税）排在 MU5101（¥940 含税）上方，但用户实际到手价可能反转。对一个"帮你找最低价"的产品，这是最容易被用户骂的公平性问题。
2. **【小体验】**"◀ 最低价"标记独占一行显示在表格行下方，第一眼不易关联到具体行。
3. **【工程卫生】**`test_no_command_returns_nonzero` 未捕获 stdout，帮助文本会混入测试输出；`alerts.json` 损坏时 `load_alerts` 静默返回空，随后的 set 操作会用空清单覆盖原文件，建议覆盖前提示或备份。
