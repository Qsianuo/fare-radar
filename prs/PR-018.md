## 设计要点

1. **不额外消耗配额**：`insights()` 只读 `offers_*.json` 缓存，缓存缺失返回 `None`，绝不回源。
2. **三入口同源**：取数与文案只写在 `fareradar.py` 一处，Web/CLI/MCP 调用同一函数。
3. **口径不混用**：`price_insights` 与 `_to_offer` 的 `total_estimate` 同为上游含税总价，
   故不换算、不叠加机建燃油，只在展示层声明"与本渠道到手价同口径"。
4. **零编造延伸**：无字段 → `None`（整块隐藏）；未知 `price_level` 原样保留不映射中文；
   脏历史点丢弃。

## 评审记录（总协调者，2026-10-25：通过）

1. **红线核查**：行情数据缺失时界面/输出整块不出现，无任何推算或占位假数据；`price_history`
   明确标注"抽样值，非逐日真实报价"。
2. **配额纪律**：`insights()` 零回源有单测锁定（`insights()` 调用不得产生任何 HTTP 请求）。

   统一品牌蓝；"偏高"用琥珀色（`--warn`）——保留既有词表规则。

## 已知限制

1. `price_history` 为上游抽样价位（61 天 6 个值），仅趋势参考。
2. 行情随缓存生命周期更新（6h），过期后首次查询才有新值。
3. 目前只有 RapidAPI·Google Flights 渠道提供该数据；其他渠道无对应能力，属正常缺省。
