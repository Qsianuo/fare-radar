# ISSUE-008: 网页上"设底价"点了没反应——关注清单一直是空的

- 提交人: 总协调者（v1.2.0 浏览器验收实测发现） | 日期: 2026-10-25 | 状态: Closed（v1.2.1 修复）
- 类型: 🐛Bug

## 问题描述（用户视角）

"我在网页的低价提醒页签里填好出发、到达和底价，点'设底价'，页面没有任何'已保存'的提示；点'立即检查'也提示'暂无关注航线'。设了个寂寞。"

## 复现步骤

1. `python src/webapp.py` 启动网页版（v1.2.0，tag 后代码）。
2. 切到"🔔 低价提醒"页签，保持默认 SHA / PEK / 800，点"设底价"。
3. 点"立即检查"。

## 预期结果

出现"已保存关注：上海(SHA) → 北京(PEK)，底价 ¥800"，关注清单出现一行，"立即检查"播报该航线判断结果。

## 实际结果

无成功提示；清单显示"暂无关注航线"；"立即检查"无逐条结果。（错误提示随后被"立即检查"的状态栏刷新覆盖，用户几乎不可能看到原因。）

## 证据（命令输出/日志摘录）

- 页面上下文诊断：表单路径提交后 `#watch-status` 显示 `接口不存在`——`api()` 辅助函数始终以 **GET** 发送请求，而服务端将 `/api/watch/set`、`/api/watch/remove` 定义在 **POST** 路由；GET 打到未知接口返回 404。
- 同一页面上下文直接 `fetch(..., {method:"POST"})` 立即成功（`{"ok": true, ...底价 ¥750}`），排除服务端问题。
- 服务端 curl `-X POST` 全链路正常（set/list/check 均正确）。

## 对用户的影响

网页版核心功能之一（低价提醒）完全不可用，且错误被界面刷新吞掉——用户只会觉得"这工具坏了"。比"崩溃"更糟的是"静默失效"。

## 对流程的启示（记录给评审）

- 单测直调 `_api_watch_set` 函数层，不经过 HTTP 路由，覆盖不到方法不匹配；
- curl 冒烟只测了"服务端认为的正确用法"；
- **只有真实 GUI 黑盒测试能暴露前端与服务端的契约断裂**——浏览器实测不是可选项。
