## 关键设计裁定

### 裁定 1：两级接口分离，价格只有一个出口

需求要求"航班查询不返回价格"，看似奇怪，实际是数据现实倒逼：

- 7 张截图是**券规则 + 适用航线 + 日期价目**，没有航班号、没有起降时刻、没有舱位；
- 春秋小程序的价目是"持卡专享价"，价格从属于**卡**而不是某个航班；
- 若航班接口顺带返回票面价，上层必然拿来与券折算价比大小，产生口径错位的结论。

结论：`spring_flights` 完全不碰价格（连 `¥` 都不出现），`spring_coupon_quote` 是唯一定价出口。

### 裁定 2：「可售商品」而不是「航班」

截图不含航班号与时刻。若把一条记录渲染成"一班航班"，就必须编造 `9C8899 08:15→10:40`
这类字段——正是 v1.5.0 明令清除的编造数据。因此：

- 每条记录的含义是**一条可售商品**（航线 + 可选日期 + 适用券）；
- `flight_no / depart_time / arrive_time` 恒为 `null`，并给出 `flight_info_disclosed=false`
  与「截图未披露航班号与起降时刻，以下单页为准」的说明。

### 裁定 3：税费口径不同不排名

初版实现按 `unit_price_cny` 直接升序取最低，自测时发现会把「含税费 ¥439」排在
「不含机建燃油 ¥180」前面，而次卡的税费口径卡面**根本没写**。这属于"给一个错口径的
最优解"，比不给结论更有害。

改为三层输出：逐券 → 按口径分组（各组最低）→ `best_unit_price_cny` 仅在**全部命中券同口径**
时给出，否则 `null` + 原因 + `cross_basis_note` 列出各组金额，把可比性判断交回用户。

### 裁定 4：未披露字段一律 NULL

卡面无有效期（次卡）、无卡费（省钱卡）、无税费口径（次卡）——全部 NULL，渲染成"未披露"。
不补默认值、不按"秋季"猜日期区间、不把 NULL 当 False。

## 已知边界

1. 无航班号/时刻（截图未披露，不生成）；
2. 不校验库存与真实可售性（静态截图）；
3. 省钱卡卡费未展示 → 单价不含卡费摊销，已在每张券标注；
4. 次卡有效期未知 → 不做日期过滤，仅警告；
5. 不爬取：数据来自人工转录截图。
