# ISSUE-004: 售罄的团购券在比价结果里照样标"◀ 最低价"，不告诉我买不到

- 提交人: User A | 日期: 2026-10-24 | 状态: Submitted
- 类型: 🐛Bug

## 问题描述（我在做什么时遇到了什么，用户视角）

我按 README 逛团购专区（`deals`），看到京沪快线那张 ¥599 的券写着"库存：售罄"。我顺手用 `search` 查了同一条航线北京→上海，结果这张**已经卖光的券**居然排第一、标着"◀ 最低价"，备注里只字不提售罄。README 开头说团购票的"坑全部写在明面上"，结果最大的坑——根本买不到——被藏起来了。我要是信了它，就兴冲冲跑去抖音 App，然后空欢喜一场。

## 复现步骤

1. 运行 `python src/fareradar.py deals --from PEK --to SHA`，确认套餐 [DY-004] 显示"库存：售罄"。
2. 运行 `python src/fareradar.py search --from PEK --to SHA --date 2026-11-10`，观察 DY-004 在结果中的位置与备注。
3. （可由总协调者补充：检查 search 结果是否读取了套餐的库存字段，以及"◀ 最低价"标记的筛选逻辑。）

## 预期结果

售罄的券要么不进比价列表，要么在备注里明确标出"已售罄/暂时抢不到"，并且不应该被标"◀ 最低价"——最低价应该是我真能买到的价。

## 实际结果

售罄券以"最低价"身份排在比价结果第一行，备注仅有"团购 ▶ 需抖音App下单｜有效期……"，无任何库存提示。

## 证据（命令输出/日志摘录/截图路径）

`deals --from PEK --to SHA`（2026-10-24）：

```
│ 价格：¥599（含税）｜库存：售罄
```

`search --from PEK --to SHA --date 2026-11-10`（2026-10-24）：

```
¥599  抖音团购源(模拟)  京沪快线 15日有效券  含税    团购 ▶ 需抖音App下单｜有效期 2026-11-01~2026-11-15
      ◀ 最低价
```

## 对用户的影响

预算敏感用户就是冲着"最低价"来的：白高兴一场、多跑一趟抖音 App 才发现抢不到，第一次就会被"这工具不靠谱"劝退。这直接打脸产品自己的核心承诺（"坑全部写在明面上"）。
