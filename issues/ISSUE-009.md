# ISSUE-009: 网页版体验反馈合集——中文化、城市全集、多票源、收藏航线、价格仪表、UI 升级

- 提交人: 产品评审人（网页版验收时逐点反馈） | 日期: 2026-10-25 | 状态: 已确认（体验升级批次，v1.3.0 实现）
- 类型: 💡体验 / ✨新功能建议（混合批次，逐点处置见 Triage）

## 问题描述（评审人原话归纳）

1. 【中文化】搜索表单里出发/到达显示三字码（SHA/CTU），下拉里几乎只剩上海、成都——要改成中文城市名；且候选城市太少，**全部加满**（覆盖主要出行城市）。
2. 【收藏航线】"低价提醒是怎么提醒的"这类解释性内容删除，改成**收藏航线**功能组件：把常查的航线存起来，一眼看到当前最低价。
3. 【术语】结果表里"抖音团购源(模拟)""模拟航司源"——"模拟"是什么意思用户看不懂，票源名称要去术语化（诚实声明保留在显著位置即可）。
4. 【实时与仪表】数据是实时的吗？价格每秒都可能上下起伏——首页做一个**大的价格显示仪表**，让波动一眼可见。
5. 【抖音多渠道】票源不能只有"抖音团购"一个：抖音还有很多途径，比如**抖音小程序（春秋航空小程序）**、直播间等。
6. 【多方向】票源更不能只局限于抖音：要有多方向渠道（如 OTA 平台等）。
7. 【UI 升级】整体页面 UI 太单调，按**顶级 UI 标准**重做。

## 对用户的影响

当前版本"能用但不像产品"：三字码劝退普通用户、票源单一且命名费解、价格没有"行情感"、界面缺乏信任感。本批次目标是把网页版从"演示工具"升级为"像个真产品"。

## 红线约束（总协调者补记，实现时不可突破）

- 诚实披露红线不放松：所有数据仍是内置演示数据，显著位置常驻声明；"演示波动"必须如实标注，不得让用户误以为是真实实时报价。
- 规则唯一来源不放松：网页与 CLI 继续共用同一批函数与适配器；新增票源全部走 Source 适配器注册表。
- 纯标准库 + 无外部 CDN 依赖不放松；命令行行为保持兼容（新票源自动进入 CLI 比价）。
