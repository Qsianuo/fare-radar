# ISSUE-009: 网页版体验反馈合集——中文化、城市全集、多票源、收藏航线、价格仪表、UI 升级

- 提交人: 产品评审人（网页版验收时逐点反馈） | 日期: 2026-10-25 | 状态: Triage 完成（7 点全部采纳：P1×6、P2×1，v1.3.0 实现）
- 类型: 💡体验 / ✨新功能建议（混合批次，逐点处置见 Triage）

## 问题描述（评审人原话归纳）

1. 【中文化】搜索表单里出发/到达显示三字码（SHA/CTU），下拉里几乎只剩上海、成都——要改成中文城市名；且候选城市太少，**全部加满**（覆盖主要出行城市）。
2. 【收藏航线】"低价提醒是怎么提醒的"这类解释性内容删除，改成**收藏航线**功能组件：把常查的航线存起来，一眼看到当前最低价。
3. 【术语】结果表里"抖音团购源(模拟)""模拟航司源"——"模拟"是什么意思用户看不懂，票源名称要去术语化（诚实声明保留在显著位置即可）。
4. 【实时与仪表】数据是实时的吗？价格每秒都可能上下起伏——首页做一个**大的价格显示仪表**，让波动一眼可见。
5. 【抖音多渠道】票源不能只有"抖音团购"一个：抖音还有很多途径，比如**抖音小程序（春秋航空小程序）**、直播间等。
6. 【多方向】票源更不能只局限于抖音：要有多方向渠道（如 OTA 平台等）。
7. 【UI 升级】整体页面 UI 太单调，按**顶级 UI 标准**重做。

## 对用户的影响

当前版本"能用但不像产品"：三字码劝退普通用户、票源单一且命名费解、价格没有"行情感"、界面缺乏信任感。本批次目标是把网页版从"演示工具"升级为"像个真产品"。

## 红线约束（总协调者补记，实现时不可突破）

- 诚实披露红线不放松：所有数据仍是内置演示数据，显著位置常驻声明；"演示波动"必须如实标注，不得让用户误以为是真实实时报价。
- 规则唯一来源不放松：网页与 CLI 继续共用同一批函数与适配器；新增票源全部走 Source 适配器注册表。
- 纯标准库 + 无外部 CDN 依赖不放松；命令行行为保持兼容（新票源自动进入 CLI 比价）。

- 分诊人: PM | 日期: 2026-10-25 | 结论: **7 点全部采纳进入 v1.3.0**（6 点按原方向执行、1 点改形后采纳）；P1×6、P2×1；三条红线全部接受为 PRD v1.3 硬约束。逐点裁决：
- 【1 中文化+城市全集】P1，体验缺陷+需求升级。Bug 性质确认：datalist 以三字码为 value、中文为 label，输入中文按值过滤几乎无候选（评审人实测"只剩一个城市"）。裁决：①改为完整中文下拉（select 全量可选，不依赖输入过滤）；②城市全集扩至 **25 城注册表**（三字码/中文名/经纬度清单见 PRD v1.3 第 4 节），"全部加满"以该清单为边界，不做无限扩张。
- 【2 收藏航线】P1，✨新功能，采纳。"低价提醒"解释性文案删除；收藏=存航线（可附带底价），收藏页一眼看到每条航线当前最低价、低于底价绿色标记；与 CLI watch 同源 alerts.json（规则唯一来源）；数据结构仅一处授权演进：底价允许为空，存量数据完全兼容。
- 【3 术语去"模拟"】P1，文案缺陷（与 ISSUE-006 同血统）。裁决：行内票源名改用户语言、去"模拟"字样；诚实披露改由"顶部常驻演示数据声明"兜底（分工见 PRD 第 5 节）；CLI 行内名同步、首行声明措辞统一为"演示数据"——披露加强而非放松。
- 【4 实时与仪表】P1，采纳但**改形**：数据不是实时行情，"每秒起伏"不采纳（会制造真实行情错觉，违反披露红线）。改为"演示波动"：分钟级确定性起伏——同一分钟内任何入口查到的价一致，分钟间可见变化，显著标注"演示波动"；首页仪表=大字号最低价+区间可视化+近 24 小时演示价格曲线（PRD 第 8 节）。
- 【5 抖音多渠道】P1，✨新功能，采纳：新增"抖音小程序（春秋航空）"与"抖音直播间"两个票源，全部走 Source 适配器注册表。
- 【6 多方向渠道】P1，✨新功能，采纳：新增"OTA 比价"票源；与点 5 合并为 **5 票源家族**（航司直连/OTA 比价/抖音团购/抖音小程序·春秋航空/抖音直播间，PRD 第 5 节）。
- 【7 UI"顶级标准"】P2，方向采纳、表述不可验收："顶级 UI 标准"不是可测试标准。裁决：PRD 给设计原则（第 9 节），验收改为原则符合性检查，不做像素稿。
- 给 PRD 的输入: 城市注册表、票源家族、任意航线定价、演示波动、收藏航线、首页仪表、UI 原则七块全部写入 docs/02-PRD-v1.3.md，验收口径见其第 10 节。
