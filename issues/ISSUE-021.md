# ISSUE-021: 整月最低参考价日历（Travelpayouts，免费、不参与比价）

- 提交人: 产品评审人（"不行啊，你再找找办法"→"B"：只做整月参考价视图） | 日期: 2026-10-25 | 状态: Closed（v1.12.0）
- 类型: ✨新功能（旁路能力，非数据源接入）
- 前序: 国内免费票价的调研见本期讨论；本单只落"哪天飞最便宜"这一件

## 为什么只做这一件事

对 Travelpayouts（Aviasales 联盟）Data API 实测后，它**不能当国内主力数据源**：

| 航线 | 2026-11 有价天数 |
|---|---|
| HRB→SYX | 143 |
| SHA→CTU | 36 |
| CAN→CTU | 16 |
| INC→PEK | 4 |
| INC→CTU | 2 |
| INC→CAN / XMN→PEK / LHW→SZX / WNZ→CAN / KMG→HGH | **0** |

10 条抽样仅 4 条有数据，主干线也可能为空；粒度只有「日期 + 最低价 + 航司 + 航班号」，
**无起降时刻/机场/舱位/机型**，且是搜索缓存价（`expires_at` 显示为小时级缓存）。

但它有一个别的渠道都没有的能力：**整月每日最低价**——正好回答"这个月哪天飞最便宜"。
因此定为：**只做旁路日历，绝不进比价行**。

## 设计

1. **新增 `offer_channel = False` 契约**（`sources/base.py`）：声明"本渠道不产出比价行"。
   引擎照常把它登记进 `unavailable`（保持"每个渠道要么有报价、要么显式说明"的不变式），
   但 CLI 与 Web 展示时过滤掉，**不误报成"本次无销售"**。
2. **适配器**（`sources/travelpayouts.py`）：`search()` 恒空、`availability()` 恒 False 并说明用途；
   独立方法 `calendar(origin, destination, month)` 返回每日参考价，缓存 12 小时。
3. **按月裁剪**：上游 calendar 返回约半年窗口（实测请求 2026-11 却返回了 12-15），
   必须按 `month` 前缀过滤，否则"整月"名不副实。
4. **零编造**：无价/脏价/非法日期丢弃；上游无数据返回 `[]`，界面整块显示"暂无参考价"而不是空白。
5. **三入口同源**：取数写在 `fareradar.month_lowest()`，CLI 打一行、Web 走 `/api/calendar`。

## 接口

`GET /api/calendar?from=PEK&to=SHA&month=2026-11`（month 缺省取当月；需 `YYYY-MM`，否则 400）

```json
{"ok": true, "month": "2026-11", "source": "Aviasales·价格日历",
 "cheapest": [{"date": "2026-11-30", "price": 1235, "flight_no": "HU7609"}, ...],
 "price_basis": "参考价（上游搜索缓存，非可售报价，不含费用明细）",
 "notice": "该月共 N 天有参考价…"}
```

## 验证

- 单测 **198 例全绿**（+7：未配 token/非比价契约/离线短路/解析排序与脏数据/缓存命中零请求/上游失败透出/空数据）。
- 端到端：
  - `PEK→SHA 2026-11` → 5 天：11-30 ¥1235 HU7609、11-28 ¥1260、11-01 ¥1267 MU5100、11-23 ¥1297、11-10 ¥1300
  - `INC→CAN 2026-11` → 0 天，提示"上游只收录被搜索过的航线，无数据不代表没有航班"
  - 非法 month → 400
- CLI 同样输出一行"整月最便宜（参考价·非可售，来源：…）"，且不再出现"无销售"误报。
- 费用：免费（联盟 token），无按次计费；缓存 12 小时。

## 已知限制

1. 覆盖取决于"有没有人搜过这条航线"，不可预期；**有则显示、无则隐藏**，不补不推。
2. 只有日期/价格/航司/航班号，**不能当报价用**，界面已标注"参考价·非可售"。
3. 价格为上游含税口径未明示，**不参与到手价排序、不触发底价提醒**。
