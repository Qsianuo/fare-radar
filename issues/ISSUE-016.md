# ISSUE-016: 价格行情参考——把上游 price_insights 接进产品（Web / MCP / CLI）

- 提交人: 产品评审人（"price_insights 介绍一下" → "可以"，批准实施） | 日期: 2026-10-25 | 状态: Closed（v1.10.0）
- 类型: ✨新功能（既有数据利用，非新渠道）
- 前序: ISSUE-015 已把 `price_insights` 记为 backlog（"API 已提供，暂未入结果行"）

## 问题

v1.9.0 起，每次真实调用都能拿到 `data.price_insights`，但 `search()` 只解析
`best_flights`/`other_flights`，缓存也只写 `expire_at`+`rows`——**行情数据在解析阶段
被丢弃，且 6 小时后再查也不存在**。产品只能回答"最低多少钱"，回答不了"这个价贵不贵"。

## 实测结构（2026-10-25 真实调用 1 次，SHA→CAN 2026-11-10，配额 1 次）

| 字段 | 实测值 | 含义 |
|---|---|---|
| `lowest_price` | 630 | **本次查询**的最低价（与比价行同源） |
| `price_level` | `"typical"` | 上游直接给出贵/正常/便宜的判定 |
| `typical_price_range` | `[440, 680]` | 常规区间 |
| `price_history` | 61 条（2026-08-26→10-25，430–640，仅 6 个不同价位） | 60 天趋势，**抽样值** |
| `currency` | `CNY` | 币种 |

**认知更正（记录在案）**：实施前曾把 `lowest_price` 理解为"历史最低"，实测证明它是
**本次查询最低价**（630 = 当日最便宜行程 9C8855 ¥630）；历史最低在 `price_history`
（430）。判断贵/便宜的正确依据是 `price_level` 与 `typical_price_range`，不是 `lowest_price`。

## 处置

- **适配器**：新增 `_to_insights()`（字段校验 + 清洗，脏历史点丢弃）；缓存结构由
  `{expire_at, rows}` 扩为 `{expire_at, rows, insights}`；新增 `insights()` **只读缓存，
  永不回源**——行情展示不能额外消耗配额。
- **同源**：引擎新增 `price_insights(sources, …)` 与 `insight_text(insight)`，
  Web / CLI / MCP 三入口共用同一函数与同一词表，不复制规则。
- **口径裁定**：`price_insights` 与 `_to_offer` 的 `total_estimate` 同为**上游含税总价**，
  故不换算、不叠加机建燃油，仅在展示层注明"与本渠道到手价同口径"（避免踩 v1.4
  "到手价统一可比"的规矩）。
- **零编造延伸**：字段缺失即 `None`（整块不显示）；`price_level` 出现未知值时原样保留、
  渲染层不映射中文（不猜）；历史价缺失或非数字的点直接丢弃。
- **兼容**：v1.9 及更早的缓存无 `insights` 字段 → `insights()` 返回 `None`，界面隐藏该块。

## 连带修复：测试体系再次漏掉离线注入（P0 工程隐患）

实施中核对配额计数发现：跑一次全量测试，真实调用从 **17/11 涨到 20/14（+3 次）**。
根因是 `tests/test_v14_features.py` 使用 `all_sources()` 9 次，却**没有** HANDOFF §6
第 1 条要求的离线注入三行——该模块自 v1.5 起就漏了，历史每次回归都在真实联网。
已在模块头部补齐注入；修复后连跑全量测试，计数器保持 20/20 不变（零真实请求）。

## 验证

- 单测：**170 例全绿（1.3s 全离线）**，新增 5 例（洞察提取/只读缓存不联网/旧缓存兼容/
  空载荷不编造/脏历史点丢弃）。
- CLI：`search --from SHA --to CAN --date 2026-11-10` 输出
  `行情参考（RapidAPI·Google Flights 口径）｜正常价｜本次最低 ¥630｜常规区间 ¥440–680｜近 61 天 ¥430–640（抽样）`。
- MCP：`search_flights` 同一行出现在航线行之后。
- Web：`/api/search` 载荷含 `price_insights`（level/lowest/range/61 点历史），仪表区
  新增"行情参考"块；内联 JS 通过 `node --check` 语法校验。
- 端到端验证使用已付费的那一次响应落缓存复现，**未额外消耗配额**。

## 已知限制

1. `price_history` 是上游**抽样价位**（61 天仅 6 个值），只能作趋势参考，不可当逐日行情。
2. 行情块依赖缓存：缓存过期后首次查询才有新行情；无缓存时整块隐藏（不显示旧数据）。
3. 月配额天花板未变（90 次），行情不额外消耗配额，但覆盖航线数仍受配额约束。
