# 低价票雷达 FareRadar v1.1.0 发布说明

| 项 | 内容 |
|---|---|
| 发布日期 | 2026-10-24 |
| 关联 | PR-002~PR-006；ISSUE-001/002/003/004/006（ISSUE-005 重复，随 001 回归关闭） |
| 升级方式 | 无需安装，拉取仓库后照常 `python src/fareradar.py …` 即可 |

## 这版解决了什么（一句话）

**"◀ 最低价"这个箭头重新值得相信了**：它现在只指向你真能买到、到手真便宜、那天真能飞的票；用不上的券会明说为什么用不上；关注文件坏了会大声警告，绝不再悄悄清空你的数据。

## 修复（Bugs）

- **【ISSUE-001/005】最低价不再被"不含税价"冒领**：排序与 `◀ 最低价` 只在含税（口径可比）报价中产生；不含税行显著标注"税费另计，到手价高于票面"，且不会触发低价提醒。此前 KIX 航线甚至把不含税价直接标成最低价。
- **【ISSUE-003】"可以出手了"不再建立在用不上的券上**：团购券"有效期"明确为**可出行窗口**——有效期不覆盖你出发日期的券，不再取得最低价标记、不再触发提醒，行内明示"有效期不覆盖 X 出发"。
- **【ISSUE-004】售罄的券不再标最低价**：售罄券保留在结果中但行内标注"已售罄，暂时抢不到"，不再参加最低价竞争——你不会再白跑一趟抖音 App。
- **【ISSUE-002】关注文件损坏不再静默清空你的关注**：`alerts.json` 损坏时，工具会明确警告"文件已损坏，本次操作已取消（你的数据不会被覆盖）"并拒绝写入；你需要手工修复或删除该文件后重新设置。
- **【ISSUE-006】黑话消失**："模拟源数据不完整：退改规则字段缺失"这类程序术语全部移出界面；退改不明的券改为人话提示——"商家未公布退改规则，此类券风险最高；下单前务必在抖音购买页核对退改条款，并截图留证"，且搜索结果中带"退改不明"标记。

## 改进

- 搜索结果的呈现顺序按"可信度"排列：可竞争最低价的报价在前，带原因披露的报价（税费另计/已售罄/有效期不覆盖/退改不明）在后。
- 当一次搜索中没有任何可信的最低价时，工具会明说"没有口径可比的最低价，原因见各行备注"——**宁可不给箭头，不给假箭头**。
- README 示例输出与实际行为逐字一致；航线说明改为"以上海(SHA)为一端的 5 条有向航线"；watch 说明改为"每次运行时检查一次"。

## 对 v1.0 用户的行为变化提示

- 同一条命令的排序结果可能与 v1.0 不同：不含税行、用不上的券会排到后面——这不是退步，是修正。
- 设置底价后没有触发提醒？先看看结果里是否有"税费另计/有效期不覆盖/已售罄"标注——工具只对"你真能买到"的最低价报警。
- `alerts.json` 损坏期间 watch 相关操作会被拒绝（退出码 2），这是刻意的数据保护，不是故障。

## 已知限制（延续 v1.0，未变）

- 全部数据为内置模拟数据；不含税票价不做税费估算，仅作"税费另计"披露；无后台轮询提醒；不支持往返/多航段/筛选/`--json`。
