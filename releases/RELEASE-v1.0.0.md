## 这版是什么（一句话）

**一个不绕弯子的命令行比价雷达**：把航司直连价与抖音团购套餐价放在一起比，价格升序、标出最低价，并把团购票的有效期、退改规则、"要去抖音 App 下单"这些坑写在明面上。

## 首发内容

### 三个命令

| 命令 | 能力 |
|---|---|
| `search` | 多票源合并、价格升序、`◀ 最低价` 标注、票源标注、票源失败降级提示 |
| `deals` | 团购专区：套餐卡五要素（价格/航线/有效期/退改规则/下单方式）+ "需在抖音 App 内下单" |
| `watch` | 低价提醒：设置/列表/删除底价；`search` 时判断命中；裸 `watch` 立即检查全部关注 |

### 架构与工程

- **可插拔票源**：统一 `Source` 抽象（`search` 比价行 / `deals` 团购卡），新增票源只需在 `sources/__init__.py` 登记一处。
- **产品代码 497 行**（约束 ≤500），**仅标准库**（argparse / json / datetime / pathlib / unicodedata），零第三方依赖。
- **21 例单测全绿**（`Ran 21 tests, OK`，留档 `tests/test-run-v1.0.log`）；零网络请求，单次命令毫秒级返回（PRD 性能要求 ≤2 秒）。
- 全中文输出，含 CJK 宽度对齐与 Windows GBK 控制台 UTF-8 重配置；错误路径统一中文报错 + 退出码 2。

### 演示数据（当时形态）

- 航司源：以上海(SHA)为一端的 **5 条有向航线**、按星期确定性浮动。
- 团购源：**5 张套餐卡**；其中 DY-005 刻意缺退改规则，用于验证"未披露"兜底。

## 已知限制（首发即披露）

1. **全部为内置模拟数据与模拟航线**；未覆盖航线输出"暂无可用报价"，不编造。
2. P2 项按计划未做：`--json`、历史价格、筛选器、颜色高亮。
3. 不做购票/支付/跳转；团购购买始终在抖音 App 内完成（无资质且涉资金风险）。
4. 中文表格对齐依赖等宽字体，比例字体终端会错位（信息不丢失）。
5. `alerts.json` 无并发锁，多终端同时写可能互相覆盖（单机单用户场景可接受）。
