# RELEASE v1.14.0 —— 没报价不等于没航班

| 项 | 内容 |
|---|---|
| 发布日期 | 2026-10-26 |
| 关联 | **ISSUE-023**｜PR-024 |
| 上一版本 | v1.13.0 |
| 升级方式 | 拉取仓库即可；无新增依赖、无新增 Key、无额外配额消耗 |

## 这版解决了什么（一句话）

上游有时返回**真实航班却不给价**（如银川→深圳 2026-10-27 的奥凯 BK3037），旧版会把整条行程丢掉，
让人以为"这条航线查不到"。现在航班照常展示，价格标「未披露」，且不参与排序与最低价判断。

## 改动前后对照

| 场景 | v1.13.0 | v1.14.0 |
|---|---|---|
| 上游返回 1 条行程、`price: null` | 结果 0 条 + 提示"未返回可售行程" | 结果 1 条，金额位「价格未披露」，附说明 |
| 排序 | 无价行不存在 | 无价行排在所有有价行之后 |
| 「◀ 最低价」/ 低价提醒 | — | 无价行不参与（宁可不标，不给假箭头） |
| 跨渠道同航班，一个渠道有价一个没价 | — | 有价行胜出，标"另有 N 个渠道有售" |
| 上游连行程都没返回 | 含糊提示 | 说明里带条数（`raw_itineraries`），区分"无排班"与"缺字段" |

## 实测（银川 → 深圳 2026-10-27）

```bash
python src/fareradar.py search --from INC --to SZX --date 2026-10-27
```

```
[提示] 本次找到 1 个航班，但上游均未提供报价（价格标为「未披露」，不做排序、不做最低价判断）。
      航班信息真实，购票前请到官方渠道核实价格。
到手价      票面价  票源                     航班/套餐            时间         税费
价格未披露  未披露  RapidAPI·Google Flights  Okay Airways BK3037  11:30→15:00  价格未披露（无税费口径可算）
```

网页端同一条查询：结果行金额位显示「价格未披露」+ 说明，结果元信息显示
「1 个结果（其中 1 条上游未给价）」。MCP 端 `search_flights` 输出 `1. 价格未披露 BK3037 …`。

## 涉及的两个渠道

| 渠道 | 触发条件 |
|---|---|
| RapidAPI·Google Flights | 行程有航段但 `price` 为 `null`（临近起飞、该日期未给价） |
| 飞常准·Aviation MCP | 航班有时刻但舱位无有效报价（空舱位表 / 非数字价 / 0 元价） |

仍会丢弃的只有一类：**缺航段或缺起降时刻**的行程——连"哪一班"都说不清，展示了反而是噪声。

## 兼容性

- `offers[].price` / `total_estimate` 现在可能为 `null`，新增 `price_note`、响应级 `no_price_count`；
  若有外部脚本直接对 `price` 做算术，需先判空（这是本版唯一的不向后兼容点）。
- 券库（`spring_flights` / `spring_coupon_quote`）**未改动**，契约与 v1.13.0 一致。
