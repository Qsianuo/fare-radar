# RELEASE v1.13.0 —— 春秋券库：航班接口不给价，价格由券规则算

| 项 | 内容 |
|---|---|
| 发布日期 | 2026-10-26 |
| 关联 | **ISSUE-022**｜PR-023 |
| 上一版本 | v1.12.0 |
| 升级方式 | 拉取仓库即可；券库为本地 SQLite，无需任何 Key，不消耗任何配额 |

## 这版解决了什么（一句话）

把春秋 7 张抖音小程序截图变成**可查询的券库**：先查"这条航线这一天有没有券可用"（不含价格），
再按券规则折算单价——**209 元秋季 2 次卡 = 104.5 元/次**。

## 新增能力

### ① 结构化入库

```bash
python src/spring_ingest.py --rebuild --show
# 入库完成：SPRING-2026-10-26
#   券 2 张 ｜ 券适用航线 101 条 ｜ 日期价目 52 条（2026-10-27 ~ 2026-11-24）
```

4 张表：`coupon`（券）/ `coupon_route`（券适用航线）/ `fare_offer`（日期价目）/
`ingest_batch`（入库批次，可追溯）。截图没写的字段一律 NULL，不做任何推算。

### ② 两级接口（本版核心约束）

| 入口 | 命令 | 是否含价格 |
|---|---|---|
| MCP | `spring_flights` | **否**（`price_returned=false`，全文无 `¥`） |
| MCP | `spring_coupon_quote` | 是（唯一定价出口） |
| Web | 页签「春秋券」→ `/api/spring/flights` + `/api/spring/quote` | 同上 |
| CLI | `python src/fareradar.py spring --from 上海 --to 大连 --date 2026-11-09` | 同上 |

CLI 输出三段，刻意让第①段不出现任何金额：

```
—— ① 可用航班/商品（2 条｜不含价格）——
1. 春秋航空·春秋省钱卡（购卡专享价）｜同日专享价在售｜日期：2026-11-09｜航班号/时刻：未披露
2. 春秋航空·209元秋季2次卡｜券适用航线可兑｜日期：不限（券未绑定日期）｜航班号/时刻：未披露

—— ② 券匹配与折算单价（2 个）——
1. 209元秋季2次卡｜折算 ¥104.5/人次/单程｜口径：税费口径未披露
   卡价 ¥209 ÷ 2 次 = ¥104.5/次
2. 春秋省钱卡（购卡专享价）｜折算 ¥130/人次/单程｜口径：票面价（不含机建燃油）
   持卡按专享价 ¥130 成交（卡面标省 ¥130）

—— ③ 按税费口径分组（口径不同不合并排名）——
· 税费口径未披露：最低 ¥104.5（209元秋季2次卡）
· 票面价（不含机建燃油）：最低 ¥130（春秋省钱卡）
```

### ③ 匹配规则（确定性，无随机）

- **次卡**：`(出发, 到达)` 在该券 101 条白名单内即命中，不看日期（卡面无有效期）；
- **省钱卡**：价目表存在 `(出发, 到达, 查询日期)` 才命中，**日期不符不外推、不取均值**；
- 方向敏感（上海→石家庄 ≠ 石家庄→上海），不做同城/邻近机场模糊匹配；
- 一次一券，不做叠加；只对春秋航空(9C) 自营生效。

## 这版不做什么（重要）

- **没有航班号与起降时刻**：截图没披露，字段恒为 `null` 并显式说明——不生成、不拼凑；
- **不给次卡编有效期**、**不给省钱卡编卡费**：卡面没写就是"未披露"；
- **不校验库存**：静态截图无法确认某天是否真有座，界面统一提示"以下单页为准"；
- **不进比价列表**：不参与 `search_flights` 的到手价排序，也不影响底价提醒（既有输出零变化）；
- **不爬取**：数据来自人工转录截图。
